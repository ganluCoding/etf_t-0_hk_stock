# 独立行情与招商证券盘口留证方案

- 状态：Approved design，尚未接入外部账户或券商
- 日期：2026-08-02
- 范围：G2 跨源数据验收与 G3 券商可执行性纸面留证；不下单、不保管凭据、不自动交易。

## 结论先行

三条证据链必须分开：

1. 当前东方财富公开源继续作为主采集源，状态保持 `UNVERIFIED RESEARCH FEED`。
2. 独立授权行情源用于核验分钟 OHLCV、时间戳、成交量/额和必要时的盘口；它只能推进 G2。
3. 招商证券客户端中用户当时真正看到的目标 ETF 盘口，加上未成交、部分成交、成交和撤单结果，才是 G3 纸面/人工执行证据。

因此，“两个行情网页价格一致”不等于招商账户可以按该价成交。

## 数据源路线

### A. 首选独立分钟源：Tushare Pro 小规模验证

Tushare 的官方接口文档显示 `rt_etf_min` 可返回 ETF 1–60 分钟 OHLCV/成交额，
`rt_etf_sz_iopv` 可返回深市 ETF 的时间、最新价和 IOPV；两者均需核实当前权限与费用。
它与当前东方财富 API 分发路径分开，适合先对 16 只 ETF 做跨源分钟验收，但不单独证明券商成交。
“不同 API”也不自动证明上游数据管线独立；权限探针必须记录数据来源说明与授权条款。
若无法确认上游数据关系，它只能记为“第二分发路径”，不能单独完成 G2 独立源验收。

接入前必须先做 1 个交易日的权限探针，检查：16 只代码的覆盖、时间标签语义、
上海/深圳差异、返回延迟、调整方式、成交量单位、频率限制和数据使用条款。
若任一核心字段不能保留原始载荷与采集时间，则不进入正式对照。

### B. 需要程序化一档/深度时的备选：富途 OpenAPI 只读行情

富途官方文档显示 A 股 ETF 可按行情权限获取 LV1，实时摆盘接口包含 bid/ask 价格、
数量和服务器收到交易所行情的时间。该路径只是备选：它需要独立登录、协议确认和行情权限。
本项目若使用，只允许启动 quote 模块，显式禁用 trade 模块；用户在官方客户端自行登录，
代码不保存账号、Cookie、Token 或交易密码。在用户确认账户/数据授权前不实施。

### C. 采集密度

- 16 只 ETF：两个数据源均保留原生 1 分钟数据，以交易日为最小质量验收单位。
- 候选池：只对当天预先登记的 3–5 只 ETF 保留 1 秒或原生 push 盘口，不对 16 只全天无差别保存秒级数据。
- 桌面人工观察仍以 5–15 秒视觉刷新即可；1 秒采样用于事后对齐和漏报识别，不会把手工交易变成高频下单。

## 招商证券盘口留证 SOP

### 首日权限探针

由用户在招商证券官方客户端手工检查，不将账户接入本项目：

1. 159567 和另一只上交所候选 ETF 是否均可显示买一/卖一价格及数量。
2. 客户端能显示五档还是仅一档，是否显示 IOPV/折溢价，并记录行情权限类型。
3. 行情页时间、系统时间和本机采集时间能否同屏或通过连续录屏对齐。
4. 截图或录屏中的账号、资产、持仓、手机号和通知必须遮罩或不出现。

### 固定样本与事件样本

每个观察日保留两类样本：

- 固定时点：09:45、10:30、13:30、14:30，对当日预登记候选各保留一次 10–15 秒连续录屏。
- 事件时点：每次人工纸面买入/卖出意图前保留盘口，随后记录在同一限价和数量下的
  `UNFILLED`、`PARTIAL`、`FILLED` 或 `CANCELLED`，不得删除未成交样本。

录屏须清楚显示六位代码、ETF 名称、最新价、买卖档位与数量、观察时间；若客户端实际不提供某字段，
则在结构化记录中明确记为缺失，不从其他源回填。

## 本机证据模型

原始行情载荷保存在 `data/raw/independent_feed/`，标准化记录保存在
`data/interim/independent_feed/`。脱敏后的市场数据可用 DVC 指针版本化。

招商原始录屏/截图保存在本机加密、Git 与 DVC 均忽略的
`data/external/broker_evidence_private/`；只在本机 SQLite 保留 SHA-256、文件路径、脱敏状态与结构化提取。
未脱敏券商媒体、交割单和账户资料永不进入 Git/DVC。

每条结构化证据至少包含：

| 字段组 | 必须字段 |
| --- | --- |
| 身份 | `capture_id`、`symbol`、`trading_name`、`source_name`、`source_permission` |
| 时间 | `source_observed_at`、`local_received_at`、`clock_offset_ms`、`session` |
| 盘口 | `last`、`bid1_price/size`、`ask1_price/size`，可用时增加 2–5 档 |
| ETF 参考 | `iopv`、`premium_discount_bps`；缺失时显式为 `null` |
| 人工意图 | `intended_side`、`intended_price`、`intended_quantity`、`recorded_before_action` |
| 结果 | `outcome`、`filled_price`、`filled_quantity`、`cancelled_at`、`outcome_reason` |
| lineage | `raw_sha256`、`extractor_version`、`manual_review_status`、`notes` |

## 对齐与验收门禁

### 时间对齐

- 采集机必须使用同步时钟，每个 run 保存时钟偏差、时区和单调接收序号。
- 优先使用源端时间；源端时间缺失时只能以本机收到时间作为上界，不伪造交易所时间。
- 分钟 bar 先核对标签语义，再按同一结束时间比较；盘口以最近事件对齐，不用未来快照回填。

### 分阶段验收

1. **1 日权限探针**：所有 16 只分钟源能返回、字段和单位可解释、原始载荷可指纹化。
2. **3 个交易日交叉核验**：这是早期数据源评审，不是策略验证。每只 ETF 输出 OHLCV/成交额差异表、
   缺失/重复、时间偏移和不同价格档的样本。
3. **20 个交日纸面执行**：保留全部固定与事件样本，包含未成交/部分成交/撤单；只有此阶段才能评估排队和成交折损。

正式验收阈值必须在采集前冻结。首版预注册为：

- 两源正常时段分钟完整率各至少 99.5%，无未解释重复；不用插值补齐验收。
- 同标签 OHLC 差异超过 1 个最小价格单位的比例、成交量/额差异和 bar 边界偏移均单独报告；
  在查明口径前 G2 不通过，不为达标而放宽。
- 与券商录屏时间对齐在 2 秒以内的盘口样本，单独统计 bid1/ask1 同价、差 1 tick 和差更多的比例；
  缺源时间或无法对齐的样本不进入一致率分母。
- 任何交叉价格、陈旧快照、买卖量缺失、标的错配或时钟回拨都 fail-closed。
- G2 通过不自动推进 G3；G3 还需要招商客户端的当时盘口、完整结果分布、费用证据和 20 日纸面执行。

## 产出与分工

| 产出 | 系统 | 用户 |
| --- | --- | --- |
| 独立源原始/标准化数据、哈希、差异报告 | 采集、计算、fail-closed | 确认数据权限/可接受费用 |
| 招商盘口原始录屏 | 不读取券商客户端 | 手工录屏、先脱敏再导入 |
| 结构化纸面结果 | 验证字段/整手/价格、保留失败 | 手工确认结果与原因 |
| G2/G3 验收报告 | 统计缺失、差异、部分成交和成本 | Review；不把报告当买卖指令 |

## 实施顺序

1. 用户确认 Tushare 权限/费用是否可接受；未确认前只做本地接口设计。
2. 实现独立分钟源 adapter、原始载荷和字段谱系，对 16 只运行 1 日探针。
3. 增加跨源差异报告和 3 日验收，不改变当前公开源的 `UNVERIFIED` 标记，直到验收完成。
4. 用户完成招商首日权限探针；系统再增加脱敏媒体元数据与纸面结果导入。
5. 对预登记候选执行 20 个交日纸面观察，最后才评估 G3；未通过时继续 No-Go。
